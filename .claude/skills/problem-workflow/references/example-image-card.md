# 完整範例：圖卡生成

這套模式最早是從產社群圖卡的流程抽出來的。把那個實例攤開來看，
比抽象講「要有標準」清楚得多——也能看出哪些部分是通用的、哪些是那個題材專屬的。

本 repo 裡 `.claude/skills/image-card/` 是這個實例的完整版本。

## 對照表

| 通用步驟 | 圖卡的做法 |
|---|---|
| 收需求 | 要什麼圖、用在哪個平台、給誰看 |
| 補規格 | 比例（由平台決定）、構圖、風格 |
| 不變的約束 | 角色設定卡：黑貓／金黃眼／米褐色偵探帽，逐字複製 |
| 驗收標準 | 角色、文字、比例、單張、構圖——五條 |
| [程式] 判的 | 比例與解析度，跑 `check_image.py` |
| [人眼] 判的 | 角色像不像、中文有沒有糊、有沒有擋到字 |
| 換路一 | 把圖上的字砍短 |
| 換路二 | 拿掉背景元素、角色縮小 |
| 做的人 ≠ 審的人 | 畫圖端只收指令交圖，不參與「要不要重畫」 |

## 從這個例子學到的三件可以帶走的事

**「不是什麼」比「是什麼」有效。** 設定卡寫「米褐色偵探帽」不夠，
要寫「鹿皮獵帽，不是棒球帽、不是紳士帽」。正面描述的解讀空間很大，
負面界定才收得住。這個技巧在任何「照規格做」的任務上都成立——
寫 API 時講清楚不該回什麼，寫文案時講清楚不要哪種開頭。

**禁止清單要明寫。** 最常出的錯都是**沒被禁止的自由發揮**：
自己把一張拼成九宮格、自己加沒要求的英文標語。
把禁止寫進規格，比事後退件便宜得多。

**能機械判的那條，一定要真的寫成程式。** 「比例對不對」用眼睛判，
1080×1080 和 1080×1350 看起來差不了多少，但一個會被平台裁掉。
寫成腳本之後，這條標準就不會因為你今天趕時間而放水——
而且腳本可以順便擋掉連看都不必看的情況（解析度太低，字一定糊）。

## 哪些是圖卡專屬、不要照搬

五條標準本身是圖卡用的。換個題材就要換標準——
寫程式是「測試過不過、有沒有破壞既有行為」，
寫文章是「有沒有錯字、長度、有沒有空話」。

**通用的是方法：明文、可逐條判、程式判的真的寫成程式、全過才算過。
不是那五條的內容。**
