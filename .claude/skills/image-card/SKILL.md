# 圖卡生成工作流

這套流程的目的，是讓人只出現在頭尾兩端：**開頭講需求，結尾看成品**。
中間的指令撰寫、送件、檢查、退圖、重寫，都不該讓人介入。

要做到這件事，關鍵不是模型更強，而是**角色分開**：寫指令和審圖的是你，
畫圖的是另一端，而且畫圖端不參與「要不要重畫」的判斷。畫的和審的是同一個，
就會自己說自己畫得好。

## 三個角色

| 角色 | 負責 | 不負責 |
|------|------|--------|
| 使用者 | 講需求、驗收成品 | 寫 prompt、看每一張草稿 |
| 你 | 寫指令、審圖、決定重畫、改指令 | 畫 |
| 畫圖端 | 畫 | 討論需求、判斷要不要重畫 |

---

## 步驟一：取得需求

需要三件事：**要什麼圖、用在哪個平台、給誰看**。

缺的一次問完，不要一題一題來回。平台尤其不能自己假設——比例由平台決定，
猜錯就是整張重畫。其他細節（構圖、配色、角色怎麼擺）不要問，那是你的工作。

## 步驟二：寫完整的畫圖指令

讀 `references/prompt-template.md`，照模板把四件事補滿：
**比例、構圖、角色長相、圖上要放的字**。

有角色的話，到 `references/characters.md` 找該角色的「指令用區塊」，
**逐字複製貼進去**。不要重寫、不要換同義詞——每次重寫長相，
就等於每次重新抽卡。

寫完之後，把完整指令留在對話裡（不要只在腦中），退圖重寫時要拿它當基準。

## 步驟三：送去畫

先看畫圖端在不在：

```bash
command -v codex
```

**有 `codex`**：用它把指令送出去。注意 OpenAI 官方文件把 Codex CLI 定位為
coding agent，**並未記載產圖功能**，實際能不能叫得動、怎麼叫，會隨版本變動。
先跑 `codex --help` 對一次你這台的能力，不要照抄舊版旗標。

**沒有 `codex`，或它叫不動產圖**：不要卡在這裡，也不要假裝畫出來了。
把完整指令用程式碼區塊輸出給使用者，請他貼到 ChatGPT 產圖、把圖帶回來。
自動化只是省掉複製貼上；**真正產生品質的是指令模板、設定卡和五條標準**，
手動跑流程一樣成立，只是慢一點。

## 步驟四：審圖

圖回來之後，先跑機械檢查，再用眼睛看。

```bash
python3 scripts/check_image.py <圖片路徑> --expect 4:5
```

這支腳本判「比例」和「解析度」兩條——這兩條用程式判比用眼睛準，
而且解析度太低的圖，上面的中文一定糊，可以在細看之前就擋掉。

其餘四條要你真的把圖讀進來看：用 Read 工具打開圖片，照
`references/review.md` 的五條標準**逐條寫判定**，不要只給一句「這張可以」。
逐條寫下來有兩個作用：退圖時能明確告訴畫圖端錯在哪，才改得動指令；
過圖時能讓人回頭檢查你是不是真的每條都看了。

**五條全過才算過。任一條沒過就是退。** 沒有「過三條算不錯」——
一旦開始通融，標準會一路鬆到跟沒有一樣。

## 步驟五：沒過就改指令重畫

退圖時改的是**指令**，不是去拜託模型再試一次。針對沒過的那條改：
文字糊 → 砍字；角色錯 → 把設定卡的「不是什麼」寫更死；
構圖壓到字 → 把位置和佔比寫得更具體。

### 重試上限

**同一張圖、同一種改法，最多試兩次。** 第二次還沒過，就不要再用同一種
方式改——問題多半不在措辭，在要求本身太難。改走兩條換路：

1. **縮短圖上的字**——文字類失敗絕大多數是字太多
2. **把畫面改簡單**——構圖類失敗靠減少元素解決

兩條都走完還是沒過，才回頭找人，而且回報的不是「畫不出來」，是
**試過哪幾種、各差在哪**，讓人能決定要放寬哪條標準或改需求。
完整的回報格式在 `references/review.md` 最後一節。

沒有上限的重試不只是浪費成本——它會讓壞掉的任務一直卡著，不會冒泡到人面前。
上限真正保護的是人的注意力。

## 這三步可以單獨用

使用者可能只要其中一段，照他要的做就好：

- **只要指令**：做步驟一、二，把指令給他，不要自作主張去產圖
- **只要審圖**（他丟一張圖來問行不行）：做步驟四，逐條判定後給結論。
  沒過的話一併給出「指令該怎麼改」，但先不要自己重畫
- **全程**：一、二、三、四、五跑完，只把過了的圖交出去
