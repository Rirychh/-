# 審核標準與重試規則

審圖要能交給別人執行，標準就必須是**明文、可逐條判斷**的。
靠「感覺好不好看」的標準沒辦法被執行，也沒辦法被檢驗——
所以下面五條每一條都有明確的過與退，不保留模糊空間。

## 一個前提：審的人不能是畫的人

畫的和審的是同一個，就會自己說自己畫得好。這套流程裡，
**畫圖端完全不參與「要不要重畫」的判斷**——它只收指令、交圖。
這不是多一道工，是整件事能成立的原因。

---

## 五條標準

全部要過才算過。任何一條沒過就是退，沒有「過三條算不錯」這種事。
一旦開始通融，標準會一路鬆到跟沒有標準一樣，而且是人要花時間重看每一張。

### 1. 角色

長相跟 `references/characters.md` 的對照清單**逐項**比對。

- **過**：清單每一項都對上
- **退**：任一項不符（黑貓變虎斑、金黃眼變綠眼、偵探帽畫成棒球帽）

沒有角色的圖卡，這條標記「不適用」，不是「通過」。

### 2. 文字

- **過**：圖上中文筆畫完整、看得懂、無錯字、全部繁體
- **退**：筆畫糊掉或扭曲、錯字、出現簡體字、出現沒要求的英文

逐字讀過去。中文字糊掉常常只有一兩個字，整體掃一眼會漏。

### 3. 比例

**用腳本判，不要用眼睛判**：

```bash
python3 scripts/check_image.py <圖片路徑> --expect 4:5
```

腳本同時會擋掉解析度太低（長邊 < 1000 px）的圖——那種圖上的中文一定糊。
exit code 0 代表這條過，非 0 代表退。

### 4. 單張

- **過**：一張圖就是一張卡
- **退**：拼成九宮格、多格分鏡、同一張圖裡放了多個獨立畫面

### 5. 構圖

- **過**：角色不擋字，也不搶主視覺；文字完整可見
- **退**：角色壓在標題上、文字被遮住或被裁掉、角色大到變成主體

---

## 判定要寫出來

審完逐條寫判定，不要只給一句「這張可以」。原因有二：
退圖時要能明確告訴畫圖端錯在哪，才改得動指令；過圖時要能讓人
回頭檢查你是不是真的看過每一條。

格式：

```
角色：✓ 全黑 / 金黃眼 / 鹿皮獵帽，三項皆符
文字：✕ 主標「量」字右半糊成一團
比例：✓ 1080×1350，4:5（腳本判定）
單張：✓ 單一畫面
構圖：✓ 角色在右下，未壓到文字
→ 退（文字）
```

---

## 重試上限

沒有上限的重試會變成無聲地燒時間：同一個問題改第九次，每次都差一點，
而且壞掉的任務一直卡在那裡，不會冒泡到人面前。上限的真正作用
不是省成本，是**保護人的注意力**。

**同一張圖、同一種改法，最多試兩次。** 第二次還沒過，就不要再用同一種
方式改指令——問題多半不在措辭，在要求本身太難。改走下面兩條換路：

### 換路一：縮短圖上的字

文字類失敗（糊掉、亂碼、簡體）絕大多數是**字太多**。砍到剩主標，
通常就過了。副標的內容搬到貼文內文，不會損失資訊。

### 換路二：把畫面改簡單

構圖類失敗（擋字、搶主視覺）靠**減少元素**解決：少一個物件、
背景再空一點、角色再小一點、留白再多一點。

### 兩條換路都走完，才找人

這時候回報的不是「畫不出來」，而是**試過哪幾種、各差在哪**。
人要決定的是放寬哪一條標準，或者改需求——這個決定需要完整的失敗紀錄
才做得出來。

回報格式：

```
這張我試了 4 次，卡在文字：

1. 原指令（主標 18 字）→ 「鍵」「鏡」兩字糊掉
2. 同樣指令重畫 → 一樣糊，換字不換位置
3. 換路一：主標砍到 9 字 → 「鏡」還是糊
4. 換路二：拿掉背景道具、角色縮小 → 文字清楚了，但角色小到看不出是咪卡

要你決定：接受第 4 版（角色偏小），還是主標再砍到 6 字內重試？
```
