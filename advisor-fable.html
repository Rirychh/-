⚖️ Claude Code 2.1.321+ · 顧問模式 · 兩分鐘設定

/advisor fable
關鍵時刻，先問過顧問再動手

設定之後，平常還是由 Sonnet 或 Opus 做事。遇到要決定做法、同一個錯誤一直重複，或準備宣告完成之前， Claude 會自己去請教 Fable——最後由主模型決定要不要照做。

這是什麼？

一句話說完：不是換模型，是多請一個顧問

/advisor fable 不會把你的主模型換成 Fable。你原本用 Sonnet 還是 Opus，設定完照樣是它在做事。改變的是：在少數幾個容易出錯的節點上，主模型會先停下來，把整段對話交給 Fable 看過，聽完建議再繼續。

這跟「你自己開另一個視窗問第二個模型」是同一件事，差別只在於——它會自己判斷什麼時候該問，而且 Fable 拿到的是完整上下文，不是你手動複製的片段。

🔄 一次顧問諮詢的完整流程

主模型

正常做事，寫 code、跑指令、改檔案

觸發

碰到關鍵節點，暫停手上動作

FABLE

讀完整段對話，給出建議

主模型

決定採納、部分採納或不採納，然後繼續

重點在最後一步：Fable 給的是建議，不是命令。決策權仍然在主模型身上——它可能聽，也可能說明理由後走自己的路。

三個會自動請教顧問的時刻

都是「人類工程師也該停下來想一下」的那種節點

🧭

要決定做法的時候

有兩三條路可以走、架構要怎麼切、用哪個套件——這種岔路口一旦走錯，後面幾十次工具呼叫都在白做。開工前先問，成本最低。

🔁

同一個錯誤一直重複

改了三次、測試還是同一行紅字——這通常代表問題不在那行 code，而在前面的假設。卡在迴圈裡的模型最需要一雙外面的眼睛。

✅

準備宣告完成之前

「做好了」是最容易說謊的一句話。宣告完成前讓顧問回頭看一次整段對話，確認需求真的被滿足、沒有偷偷縮小範圍。

🙋

你自己開口要的時候

不等它自己判斷，直接在提示裡寫「這題先問一下 Fable 的意見」，它就會當場去諮詢。等於手上隨時有一張可以打的求救牌。

為什麼這樣分工有效？

做事的人跟檢查的人，本來就不該是同一個

一、做事的人會被自己的脈絡綁住。主模型跑了二十輪工具呼叫之後，整個注意力都黏在「我現在正在修的這一行」上。它很難退一步問「我一開始的方向是不是就錯了」——因為那等於推翻自己前面二十步。

二、顧問讀的是整段對話，不是片段。Fable 拿到的是從你第一句需求到現在的完整記錄。它看得到「使用者一開始要的是 A，但做到一半不知不覺變成 B」這種漂移，而身在其中的主模型往往看不到。

三、建議權跟執行權分開，才不會互相干擾。顧問不接管鍵盤，只給意見；主模型保留判斷。這樣既拿到第二視角，又不會讓兩個模型互相覆蓋對方的工作。

💡 808AI 的白話解釋

把它想成工地：Sonnet / Opus 是師傅，負責動手施工；Fable 是請來的結構技師，不碰工具，但在「要選哪種工法」、「同一面牆裂三次」、「要驗收了」這三個時候過來看一眼。師傅可以不聽技師的，但至少聽過了。

1. 四步設定

沒有設定檔、沒有 API key，兩分鐘以內

把 Claude Code 更新到 2.1.321 以上

這個指令需要 2.1.321 或更新的版本。先確認目前版本：

# 查版本
claude --version

版本不夠就更新：

# 更新（內建更新器）
claude update

如果你當初是用 npm 全域安裝的，也可以改用 npm install -g @anthropic-ai/claude-code@latest。更新完重開一次 Claude Code。

輸入 /advisor fable

在 Claude Code 的輸入列直接打：

# 在 Claude Code 裡輸入
/advisor fable

看到 Advisor set to 的回覆，就代表設定好了。不需要重開、不需要改任何設定檔。

照常做事就好

設定完不用改變任何使用習慣。該怎麼下指令就怎麼下，顧問會自己在該出現的時候出現。

如果你想要它現在就去問，直接在提示裡講明白即可，例如：「這個架構先問一下 Fable 的意見再動手」、「宣告完成前請顧問看一遍」。

不想用了就關掉

# 關閉顧問模式
/advisor off

關掉之後就完全回到原本的行為，不會留下任何殘留設定。隨時可以再打開。

2. 指令速查

總共就這幾個，記不起來也沒關係

/advisor fable

開啟顧問模式，指定 Fable 當顧問

/advisor off

關閉顧問模式，回到原本行為

claude --version

查目前版本，必須 ≥ 2.1.321

claude update

更新 Claude Code 到最新版

⚠️ 設定前先確認這兩件事

版本不夠會找不到指令：2.1.321 以前的版本沒有 /advisor，輸入後不會有 Advisor set to 的回覆。先更新再試。
顧問諮詢會多花一次模型呼叫：每次觸發都是額外一輪，長任務下來會累積。覺得吃不消就 /advisor off，需要時再臨時打開。

3. 什麼情況值得開？

不是每個任務都需要顧問——開錯場合只是多花錢

值得開可以不用開
任務長度要跑很多輪、會持續一兩個小時的大工程改個錯字、跑個指令這種一兩步的小事
任務性質架構決策、重構、要動到很多檔案的改動有標準答案、照著做就好的例行工作
你的狀態你人不在旁邊、沒空盯著每一步你全程看著，自己就是那個顧問
風險走錯方向代價很高（上線、資料、金流）做壞了隨時可以 undo 的實驗
💡 808AI 的用法建議

別整天開著。最划算的用法是「平常關著，遇到硬仗才開」——要重構、要動架構、要交付給客戶的東西，開工前打一次 /advisor fable，做完 /advisor off。

卡住時當求救牌打。同一個錯誤已經繞第三圈了，與其再讓它試第四次，不如開顧問模式，或是直接在提示裡要求「先問 Fable」。繞不出來的迴圈，多半要靠外面的視角打破。

把它當驗收關卡。如果你最在意的是「它說做好了，但其實沒做好」，那顧問在「宣告完成之前」這個觸發點，就是整個功能最值錢的地方。

4. 常見問題

設定之後，是不是就變成 Fable 在幫我做事？

不是。做事的仍然是你原本的 Sonnet 或 Opus。Fable 只在被請教的時候出現，給完建議就退場，不會接手任何實際操作。

主模型一定會照 Fable 的建議做嗎？

不一定。Fable 給的是意見，最後由主模型決定要不要照做。這是刻意的設計——顧問如果能直接推翻執行者，就不叫顧問了。

Fable 看得到我的完整對話嗎？

會。它會讀完整段對話再給建議——這正是它能看出「方向跑偏了」的原因。如果你的對話裡有敏感內容，開顧問模式前自己先衡量一下。

輸入 /advisor fable 沒反應 / 找不到這個指令

  • 先跑 claude --version，確認版本有沒有到 2.1.321
  • 版本不夠就 claude update，更新完重開 Claude Code 再試一次
  • 成功的話會看到 Advisor set to，沒看到就是還沒設定成功

設定會一直留著嗎？

不想要就 /advisor off，立刻回到原本行為。808AI 的建議是平常關著、硬仗才開，而不是設定完就忘記它的存在。
